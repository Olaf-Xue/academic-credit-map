# 学程管家

**学业学分进度图谱小程序** — 把学院《培养计划书》结构化为「学期 × 课程类别」的学分进度图谱，显示各模块已修/缺口，为选课提供可验证依据。

浙大城市学院 软件工程 2024 级 · 课程设计项目 · 3 人团队

## 环境准备

1. **Node.js 18+** — 用于生成文档、跑领域层单元测试。
2. **微信开发者工具**（稳定版）— 小程序开发调试。
3. 安装依赖：
   ```bash
   npm install
   ```
4. 重新生成文档（改完 `tools/gen-docs.js` 后执行）：
   ```bash
   npm run docs
   ```

> 小程序项目本身尚未创建。W-03 会由组长初始化 `miniprogram/` 与 `cloudfunctions/` 骨架，届时本 README 会补充导入步骤与云开发环境 ID。

## 协作流程

### 分支

```
main            始终可交付，只接受 PR 合入，不直接 push
  └─ feat/xxx   每人每模块一个分支，从 main 切出
```

按模块而非按页面分工（见计划书表 7-1）：

| 成员 | 负责 | 主要目录 |
|------|------|---------|
| 组长 | 数据模型、领域层、云函数 | `src/domain/`、`cloudfunctions/` |
| 前端 | 图谱渲染与页面 | `miniprogram/pages/`、`miniprogram/components/graph/` |
| 数据与测试 | 方案数据、录入页、测试与文档 | `data/`、`tests/`、`docs/` |

### 日常

```bash
git checkout main && git pull           # 开工前先同步
git checkout -b feat/graph-layout       # 从 main 切分支
# ... 改代码，小步提交 ...
git push -u origin feat/graph-layout    # 推到 GitHub，开 PR
```

### 提交信息

沿用现有约定，中英皆可，但要写清做了什么：

```
feat:  新增功能          fix:   修复缺陷
docs:  文档变更          test:  测试相关
refactor: 重构           chore: 构建/配置
```

### 三条必须遵守的规则

**1. 领域层是纯函数，不引云开发 SDK**
`src/domain/` 下的代码必须能在 Node 里直接跑测试。这条边界保证了计算引擎可独立验证，也保证将来换后端时只改 Repository 层。

**2. 前端不做任何学分计算**
课程状态（已通过/须重修/可选/暂不可选/已超出要求）与配色一律由后端下发。图谱布局也在领域层（输入状态、输出像素坐标），`GraphCanvas` 只负责绘制与触摸命中。

**3. 真实学生数据不进仓库**
内测用的成绩单属于个人信息。仓库里只放脱敏或构造数据；`.gitignore` 已排除 `data/raw/` 与 `data/real/`。截图、导出表同理，不要传到 issue 或群里。

### 云开发环境约定

- 每人使用**自己的 dev 环境**，或在自己负责的集合名加成员前缀，避免三人同时写同一份数据互相覆盖。
- `prod` 环境只有组长可写。
- 环境 ID 与各人 AppID 写在本地，不要提交（`project.private.config.json` 已排除）。

### PR 合并

- 至少一位其他成员过目，涉及领域层的改动由组长审。
- 改动 `CLAUDE.md`、数据模型、计算口径的 PR，必须在描述里写清为什么改——这三处是一期的核心资产，随意改动会让二期的抽取工作作废。
